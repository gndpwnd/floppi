**The discriminator is COOPERATION, not the technique.** A technique does not belong to a repo; a
*situation* does. Consequence, and it has already caught one error: **cooperative infrastructure TDOA**
— synchronised anchors transmitting beacons, a cooperating tag listening — is
`position_denial_research`'s, **not** hiverf's, even though "TDOA" is on hiverf's list. The SwarmLoc UWB
extract initially ceded it on the strength of the word alone. `01_target_repos_v2.md` §1.5 independently
puts "Multilateration/TDoA/TWR derivations" in `position_denial_research`'s scope.

So the test runs: *is the emitter cooperating with me?* Yes → cooperative side. No → hiverf. Apply that
before reaching for the technique list.

## 5. Gates — hazards that must be handled before/during any content copy

These are the "bite silently" items: each one fails without an error, and is discovered later as an
inexplicably heavy repo, a lost record, or a surprise background job.

### Gate 1 — R6 is directional
Writing INTO a legacy repo is forbidden (no delete, no modify, no branch work, no cleanup commits, no
`.gitignore` edits). Taking findings and useful items OUT is allowed and expected, selectively and with
attribution — never a wholesale `cp -r`. Full statement in the R6 box near the top of this document.

### Gate 2 — no git or GitLab CRUD by any session
Operator-only, both forges. Applies to repo creation, deletion, rename, transfer, and every git write.

### Gate 3 — content-based binary filter (a glob will NOT catch these)
`auto_orientation` and `flight_controller` carry **exactly 20** compiled ELF test binaries **outside**
`.pio`, with **no file extension**, sitting beside their sources — e.g. `tests/test_quaternion` next to
`test_quaternion.cpp`. Named so far: `test_quaternion`, `test_plant_identifier`,
`test_noise_floor_estimator`, `test_balance_app_bootstrap`, `test_position_gain_derivation`,
`test_balance_app_soft_cutoff` (+14 more).

`--exclude=*.elf` / `--exclude=*.bin` silently miss **all 20**. Use the content check, post-copy:

```
find <target> -type f -exec file {} + | grep ELF | cut -d: -f1 | xargs rm
```

Prefer this over an enumerated `--exclude-from` list: the enumeration goes stale the moment anyone
rebuilds; the content check never does. The same hazard class applies to any ROS2 build output if WayfindR
content is copied. *(Finding: `lowprofiledronegurus` session, verified with `file`.)*

### Gate 4 — floppi's git hooks fire ResearchHub, and the timing matters
`/home/devel/floppi/.git/hooks/post-commit` and `post-merge` both background
`python3 /home/devel/researchhub/scripts/backup/cli.py repo`. So an operator commit in floppi is **not**
the locally-contained action a checklist step implies — it triggers background load on a host that is
memory-constrained. This is **timing-sensitive, not merely surprising**: ResearchHub's own session
reported riding an OOM sawtooth, and swap was measured at 19Gi/19Gi used with 184Mi free at its worst
(recovered to ~3.5Gi free after the operator closed Chrome — not a comfortable margin). Check host memory
before any commit step, and add a line to `09_gitlab_operations_checklist.md`.

### Gate 5 — N-10: does git history travel? **RULED 2026-08-19 — NO.**
A `cp -r` / `rsync -a` migration abandons **100% of commit history** for every source, and with it every
co-author's contribution record. **Four identities** appear across the sources: `msc_intra`, `gndpwnd`,
`kaleldev`, and `Emmett M. Gilbert`. Because it concerns other people's attribution, it is squarely the
operator's decision.

**RULING (operator, 2026-08-19):** *"i really don't want to transfer git history at all that is way too
much of a mess and burdensome, its not like we are deleting ~/floppi/ so we can always reference it if we
are missing something."*

**New repos start at commit 1. No history import. A `PROVENANCE.md` per repo carries the pointer back.**
Template + the per-repo "what is worth going back for" lists: `18_provenance_template.md`.

**Argument that lowers the stakes:** under **R6** the legacy repos persist read-only and are never
deleted, so `msc_intra`'s and `Emmett M. Gilbert`'s commit records survive in `~/SwarmLoc`,
`~/GravityProbe` and `~/WayfindR-driver` indefinitely. A fresh import therefore does not *destroy* the
record, it merely does not *carry* it — and `PROVENANCE.md` bridges that. Under the earlier
"deleted in the long run" framing the same choice would have been irreversible.

### Gate 6 — check `.git` health before assuming a repo needs a rewrite
`du -sh .git` cannot distinguish real history from wreckage, and the remediations are unrelated. Run:

```bash
grep -E 'refs/(original|replace)' <repo>/.git/packed-refs ; git -C <repo> count-objects -vH | grep garbage
```

Every repo in this family with a `.git/filter-repo/` directory had a history operation left half-finished
(floppi, hiverf, engineer360 — 3 for 3), but **severity is not uniform**:
- **floppi** — `refs/original/refs/remotes/origin/main` = `f2c84a72` is stale litter from a **completed,
  pushed** operation (`HEAD` == `origin/main` == `dd39f23`). `garbage: 0`, `size-pack: 146.64 MiB`,
  617 loose objects, `prune-packable: 48`. Optional tidying, **not** a cleanup target. Hold until after any
  content copy so nothing shifts mid-migration. Operator-only:
  ```bash
  git -C /home/devel/floppi update-ref -d refs/original/refs/remotes/origin/main
  git -C /home/devel/floppi gc --prune=now
  git -C /home/devel/floppi count-objects -vH   # verify
  ```
- **engineer360** — a genuinely unfinished rewrite (local vs remote diverged since 2026-05-18) plus
  **1.80 GB of orphaned `tmp_pack_*`** that git reports as garbage: 46% of its 3.9 GB `.git` is wreckage a
  plain `rm` clears. `du` would have misdiagnosed this as needing a history rewrite.

*(Finding: `hiverf` and `lowprofiledronegurus`; floppi figures re-measured independently 2026-08-19.)*
