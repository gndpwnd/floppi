## 3. Security / correctness review (per change)

### 3a. `USE_API_AUTH` token auth — SOUND (with nits)

- **Enforced on every command path?** Yes. POST `/api/commands`: the body callback computes
  `httpAuthorized(request)` (header `X-Floppi-Token`) and, after JSON parse, rejects with
  401 unless `authed || jsonAuthorized(doc)` — *before* `setWifiCommandChannels()`. WS
  `/ws`: inside `WS_EVT_DATA`, after a successful `deserializeJson`, `if(!jsonAuthorized(doc)) break;`
  runs before any channel extraction. The `break` exits the `switch` (the intended
  "drop frame" behavior) and never reaches `setWifiCommandChannels()`. **No bypass found.**
  Chunked POST bodies early-return on incomplete chunks but never touch the command buffer
  until the final chunk, which is gated — no partial-write bypass.
- **No second command sink:** `setWifiCommandChannels()` is the only path from the network
  into the command buffer, and both call sites are gated. Telemetry read paths
  (`/api/status`, `/`, WS broadcast) are intentionally left open — acceptable per design.
- **Timing-safety:** `tokenMatches()` accumulates XOR diff over the full expected length and
  folds in a length-mismatch term, so it does not early-out on first mismatch. Reasonable
  for a short token on Core 1. NIT: it is not perfectly constant-time (it indexes the
  candidate with a branch `i < cl ? ... : 0`, and `strlen(candidate)` itself is
  data-dependent), but on a plaintext-LAN control-plane gate this is not a meaningful leak —
  and the header comments already concede confidentiality is out of scope (SEC-06).
- **Guard coherence:** `#ifdef USE_API_AUTH` → `#error` if `FLOPPI_CMD_TOKEN` undefined.
  Good. The placeholder token in `wifi_credentials.h` is `"CHANGE-ME-floppi-token"` —
  documented as a public default; a build with auth on but token unchanged compiles and
  "works" but provides no protection. This is the same ergonomic risk OTA chose to block
  with `#error`; here it is only a comment. NIT (non-blocking): consider a
  `#warning` if `FLOPPI_CMD_TOKEN` still equals the placeholder, mirroring OTA's stance.
- **SEC-01 default warning:** With `USE_WEB_SERVER` on and `USE_API_AUTH` off the
  `#warning` fires (verified). It lives in `config.h`, so it is emitted **once per
  translation unit** that includes config.h — i.e. ~14 copies per ESP32 build. Loud but
  harmless; arguably noisier than necessary (could be scoped to web_server.cpp only). NIT.

### 3b. OTA password + build guards — SOUND

- File-scope `#error` if neither `OTA_PASSWORD` nor `OTA_PASSWORD_HASH` defined; in-body
  `static_assert(sizeof(OTA_PASSWORD) > 1)` (empty rejected) or
  `static_assert(sizeof(OTA_PASSWORD_HASH) == 33)` (must be 32-char MD5 + NUL).
- Verified out-of-tree with `g++`: empty password → compile error; valid password →
  compiles; wrong-length hash → compile error. The guard genuinely prevents a passwordless
  OTA image.
- All guards sit inside the `#if defined(USE_ESP32) && defined(USE_OTA)` block, so they only
  fire when OTA is actually compiled — coherent with the flag cascade. Default esp32 build
  (USE_OTA on) compiles because the placeholder password satisfies `sizeof > 1`. Prefers the
  hash form when both are defined (keeps plaintext out of flash). Correct.

### 3c. Madgwick NaN guard — SOUND, nominal path unchanged

- The gradient normalization is now skipped when `gradNormSq <= 1e-12` (the degenerate
  exact-gravity case where `invSqrt(0)=inf → 0*inf=NaN`). When skipped, the correction is
  mathematically zero anyway, so the nominal path is bit-identical to before for any real
  (non-degenerate) IMU sample. The final quaternion norm is guarded the same way, with a
  reset-to-identity backstop on non-finite/zero-norm. `isnan` resolves via the Arduino
  framework (firmware builds clean on all three envs); the native copy uses `std::isnan`.
- The reset-to-identity is a reasonable failsafe: a one-step attitude reset is far safer
  than a permanently NaN-poisoned estimate, and it can only trigger on an already-broken
  state. **Truly unwedgeable** as claimed. No nominal-path regression.

### 3d. GPS position gate — SOUND, default sane

- `GPS_TELEMETRY_INCLUDE_POSITION` defaults to **1** (full passthrough — preserves the
  existing swarm_api contract). When 0, both `web_server.cpp` and `api_client.cpp` omit the
  `nmea` field (the *only* carrier of lat/lon on a passthrough FC) and emit only
  `gps.ok` + `gps.age_ms`. Confirmed `gpsTelemetryOk()` (`src/gps.cpp:222`) returns a pure
  boolean liveness with no coordinates, and `age_ms` is a millisecond age — neither leaks
  position. The gate genuinely withholds position. NIT: the OPSEC path still calls
  `gpsTelemetryNMEA()` into a discarded buffer just to get the age (acknowledged in-comment);
  harmless, minor waste.

### 3e. I2C command checksum (ISR) — SOUND

- The ISR (`onI2CReceive`) now prefers a 13-byte frame (12 data + XOR-of-12 checksum),
  computes the XOR while reading, and only calls `i2cApplyData()` if it matches; mismatches
  drop silently and keep the last good command. A 12-byte legacy frame is accepted only when
  `USE_I2C_CMD_CHECKSUM` is *not* defined; defining it makes the checksum mandatory. Any
  other length drains the bus to avoid desync. Logic mirrors the existing Serial protocol.
- **ISR safety:** the work done in the ISR is small and bounded (reads ≤13 bytes, one XOR,
  six 16-bit stores) — appropriate for a Wire `onReceive` callback, no blocking/alloc/Serial.
  The reader `readI2CCmd()` copies under `noInterrupts()/interrupts()`, so the ISR↔loop
  handoff of `i2cCmdChannels/timestamp/ready` is race-safe. No regression.

### 3f. Dynamic WS telemetry buffer (SEC-05) — SOUND

- The WS broadcast replaced a fixed `char buf[512]` (which could silently truncate to
  invalid JSON once GPS NMEA + baro both present — verified worst case compiles at higher
  flash) with `String out; serializeJson(doc, out)`, matching the approach `/api/status`
  already uses via `AsyncJsonResponse`. Zero-length result (alloc failure) skips the frame
  with rate-limited logging instead of emitting broken JSON. Core 1 only; flight loop
  untouched. Reasonable; the only cost is heap churn on Core 1, acceptable for telemetry.

## 4. Flag-interaction sanity

- **USE_API_AUTH × USE_OTA × USE_GPS:** independent and coherent. Auth gates the command
  surface only; OTA gates flashing; GPS gate affects telemetry content. All three verified to
  co-compile (`USE_API_AUTH + USE_GPS` built; OTA on in every default esp32 build). No
  conflicting macros.
- **`#error` vs `#warning` placement:** OTA uses `#error` (hard block — no passwordless
  image possible). API auth uses `#error` only for *missing token when auth is on*, and a
  `#warning` for *auth-off* (keeps default builds compiling — correct, since auth-off is the
  documented backward-compatible default). GPS pin defaults are `#ifndef`-guarded so a build
  flag or future pin header still wins. All consistent with the project's "default builds
  compile unchanged" rule.
- **Core-0 flight loop:** none of these changes touch the Core-0 stabilizer path. Auth, WS
  buffer, GPS gate, and OTA all run on Core 1 / in async callbacks. The I2C checksum is in an
  ISR feeding the existing command buffer the loop already polls. The Madgwick guard runs in
  the attitude estimator but adds only two cheap branches on the nominal path. **No Core-0
  regression.**

## 5. Issues

**Blocking:** none.

**Nits (non-blocking, optional follow-ups):**
1. `FLOPPI_CMD_TOKEN` placeholder offers no protection if left unchanged with auth on —
   consider a `#warning` mirroring OTA's stance (auth itself correctly requires the macro to
   exist via `#error`).
2. SEC-01 `#warning` in `config.h` is emitted once per TU (~14× per ESP32 build) — loud;
   could be scoped to `web_server.cpp`.
3. `tokenMatches()` is "constant-time-ish," not strictly constant-time (length-dependent);
   acceptable given the plaintext-LAN threat model already documented (SEC-06).
4. OPSEC GPS path still serializes NMEA into a throwaway buffer just for the age.

## 6. Verdict

**GO — safe to commit.** All three default envs build (Teensy/ESP32/ESP32-S3), all
representative flag combinations build, native tests are 5/5 green, and every change is
sound: the token check has no command-path bypass, the OTA guard provably blocks a
passwordless image, the Madgwick guard is nominal-path-neutral and unwedgeable, the GPS gate
genuinely withholds position with a sane (contract-preserving) default, and the I2C ISR
checksum is race- and ISR-safe. The four nits are quality-of-life, not correctness or
security holes, and can be deferred or addressed at the author's discretion.
