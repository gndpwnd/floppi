# tools/sim — Balance-bot simulator + offline tuner

Python harness for **offline** tuning of the Uno-minimal balancing program. The Uno does not auto-tune itself; this directory produces the fixed PID + PWM constants it ships with.

The Mega-universal balancer does its own on-MCU tuning (BOOTSTRAP + RLS) and does **not** consume the output of this directory — see [`../../docs/MEGA_UNIVERSAL_PLAN.md`](../../docs/MEGA_UNIVERSAL_PLAN.md). Use this directory only for the Uno path.

---

## Contents

| File | Purpose |
|------|---------|
| `balance_bot_sim.py` | Plant model: rigid two-wheel inverted pendulum + DC-motor + BNO055-style IMU noise. Importable; also runnable as a single-rollout demo. |
| `brute_tune.py` | Search harness: runs many simulated balance trials over candidate `(Kp, Ki, Kd, PITCH_OFFSET_DEG, PWM_MAX)` tuples and emits the winning constants as a C++ header. |
| `balance_constants_template.h.in` | Template consumed by `brute_tune.py`. Generates the `constexpr` header the Uno build pulls in. |
| `output/` | Conventional drop location for per-run logs / generated headers when not writing directly into the source tree. |

Hard constraint: stdlib + numpy only. No DEAP, no scipy.optimize. The GA is hand-coded — "brute force" is the point.

## How to run

From `auto_orientation/`:

```bash
# Quickest: random sampling, 1000 trials, write the generated header into the Uno source tree
python3 tools/sim/brute_tune.py \
    --mode random \
    --budget 1000 \
    --output src/applications/balancing_robot_uno/balance_constants.h

# Coarse grid + refinement around the top hits
python3 tools/sim/brute_tune.py --mode grid --budget 2000 \
    --output src/applications/balancing_robot_uno/balance_constants.h

# Pure-Python GA (tournament + uniform crossover + mutation)
python3 tools/sim/brute_tune.py --mode evolutionary --budget 5000 \
    --output src/applications/balancing_robot_uno/balance_constants.h
```

Available search modes: `grid`, `random`, `evolutionary`. Run with `--help` for the full flag list (plant overrides, seed control, disturbance magnitude, fitness weights, etc.).

## Expected output

`brute_tune.py` writes a single `constexpr`-only header that looks like:

```cpp
// AUTO-GENERATED by tools/sim/brute_tune.py — DO NOT HAND-EDIT
namespace balance {
constexpr float KP = ...f;
constexpr float KI = ...f;
constexpr float KD = ...f;
constexpr float PITCH_OFFSET_DEG = ...f;
constexpr int   PWM_MAX = ...;
constexpr int   PID_SAMPLE_MS = ...;
constexpr int   MIN_PWM = ...;
}  // namespace balance
```

The header preamble records the search mode, budget, seed, plant preset, achieved fitness, and tip time so a future reader can reproduce the run. The reference (manually-tuned working bot from `archive/balancing_robot_reference/SelfBallancingRobot3.ino`) is `Kp=65, Ki=12, Kd=38, PITCH_OFFSET=-8.6, PWM_MAX=255` — output sanity-check against that.

The console also prints best-candidate stats: time balanced, RMS pitch error, RMS PWM jerk, tip flag.

## Consumer

The generated header is `#include`d by the Uno-minimal application:

- `src/applications/balancing_robot_uno/balance_constants.h` (default `--output` target)
- Pulled in by `src/applications/balancing_robot_uno/balance_uno_app.cpp` (PID loop, ~150 LOC ceiling)
- Reflashed via the `arduino_uno_minimal` build env

See [`../../docs/applications/balancing_robot_uno/README.md`](../../docs/applications/balancing_robot_uno/README.md) for the end-to-end re-tune-and-reflash workflow and [`../../docs/applications/balancing_robot_uno/INDEX.md`](../../docs/applications/balancing_robot_uno/INDEX.md) for the (currently sparse) application doc map.

## When to re-run

Re-run `brute_tune.py` and reflash the Uno whenever any of these change:

- Battery chemistry / voltage range
- Wheel diameter / surface grip
- Payload mass distribution
- Motor wear that the bench operator can feel

The Uno program has **no online adaptation** — every change is an offline-tune + reflash. If you find yourself re-tuning more than once per session, that is the signal you have outgrown the Uno path and should be targeting the Mega-universal sibling instead.
