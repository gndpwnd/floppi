RECOVERY METHODS AT A GLANCE:
=============================

Method 1: Press RESET Button (1 minute, 80% success)
  - Start upload
  - Press RESET button when you see "Uploading..."
  - Release after 1 second
  - Upload completes

Method 2: Unplug/Replug USB (2 minutes, 70% success)
  - Unplug USB from Mega
  - Wait 2 seconds
  - Start upload
  - Plug USB back in when you see "Connecting..."

Method 3: Different USB Port (2 minutes, variable success)
  - Update platformio.ini upload_port = /dev/ttyUSB0
  - Try upload

Method 4: Slower Baud Rate (5 minutes, 95% success)
  - Edit platformio.ini
  - Change upload_speed from 115200 to 57600
  - Try upload (will be slower but more stable)

Method 5: Automated Recovery (5-30 minutes)
  - Run: ./tools/recover_bootloader.sh
  - Follow interactive prompts

Method 6: ICSP Re-Flash (1-2 hours, if bootloader erased)
  - Requires ICSP programmer
  - See: bootloader_recovery_guide.md Part 4

ROOT CAUSE IN SIMPLE TERMS:
============================
Linux handles the USB reset signal (DTR) differently than Windows:
- Windows: Reset happens immediately and reliably (~20ms)
- Linux: Reset is delayed and variable (~100-500ms)

The bootloader has an 8-second window to listen for upload data,
but avrdude gives up after 1 second if the bootloader doesn't respond.
When Linux delays the reset, the bootloader isn't ready when avrdude
sends the first message, causing a timeout.

Solution: Bypass the timing issue by manually resetting (press button)
or give the bootloader more time (slower baud rate).
